# keyword-judge · 关键词判定器

**取词流程里的辅助工具**：把「这个关键词值不值得做」的判断门槛固定下来，用实测数据算出「通过 / 待定 / 淘汰」，并写清哪一项过了、哪一项超了、超了几倍。

它不替你找词、不替你搜 SERP、不替你查搜索量——那些仍要你在 Trends、Ahrefs、Google 里做。它只负责**判断**这一件事，把凭感觉放行的那一步变成可复核的算术。

- 线上：<https://keyword-judge.sevenqi0728.workers.dev>
- 本地：直接双击 `public/index.html`（纯前端功能全可用）
- 形态：单文件前端 + 一个 fetch 代理 Worker，无构建、无第三方依赖（截图识别按需从 CDN 加载 Tesseract.js）

> 本文档与 `public/index.html`、`src/worker.js` 当前版本（2026-11-17）逐项对应；文中所有示例输出均为真实运行结果，不是手写示意。

## 一、用途与定位

### 1.1 它解决什么问题

选词决定上限。建站、优化、外链都只是在放大一个选择——选择错了，后面每一步都是浪费。

判断一个词值不值得做，要看四五项独立指标，每项都有门槛。人脑记不住这些门槛，于是容易"看着还行"就放行。工具把门槛写成代码，把判断过程显性化。

典型使用场景：

- 手上有 20 个候选词，需要一个统一口径快速淘汰，而不是每个词都重新纠结一遍标准；
- 拿不准某个词，想知道"按严格档是不是已经超了、超几倍"；
- 已经决定要做，需要一份带时间戳的记录，回头复盘当时凭什么做的决定。

### 1.2 它在取词流程里的位置

对应教程《第 2 步：找需求定关键词》。工具只站在**判定**这一个环节上，前后都靠人工：

| 环节 | 做什么 | 谁来做 |
| --- | --- | --- |
| ① 发现需求 | Trends 里找起量的词、看相关查询、看对比倍数估搜索量 | 人（工具只提供「看 Trends」入口） |
| ② 看供给量 | 搜 `intitle:"关键词"`，读结果数 | 人取数，工具算 KGR 与供给阈值 |
| ③ 看竞争度 | Ahrefs 查 KD 与所需外链站数 | 人取数（工具只负责打开页面） |
| ④ 看趋势形态 | 12 个月 / 5 年曲线判断形态 | 人判断，或 CSV / 走势图交给工具识别 |
| ⑤ 看前 10 构成 | 搜一遍，看是专站首页还是大站内页 | 人看，可把 URL 交给「抓取分析」辅助 |
| **⑥ 判定** | **按固定门槛合成结论，留下理由与记录** | **本工具** |
| ⑦ 建站上线 | 按词做页面、上线、请求收录 | 人 |
| ⑧ 复盘 | 收录天数、曝光点击、做错什么 | 人（工具只导出记录表） |

所以它的定位是**判定器 + 记录器**，不是选词器。判断所需的一手数据全部来自外部工具，这也决定了它的准确性上限：**输入错，结论必错**，工具只能保证"给定这些数字，结论一致且可解释"。

### 1.3 它明确不做的事

- 不自动搜 Google/Bing 拿 SERP（实测反爬无免费可靠路径，详见「八、SERP 抓取分析」）
- 不查搜索量、不查 KD（只提供跳转入口）
- 不替你判断趋势"像不像季节"——识别只是给参考，最终形态由你在下拉框确认
- 不保存任何数据到服务器（记录与草稿都在你自己的浏览器里）

## 二、快速上手

1. 在 Google Trends 找词，在 Google 与 Ahrefs 取数（页面每个字段旁有跳转按钮，见 4.4）
2. 数据填进左侧，带 `*` 的为必填
3. 点「判定」或按 `⌘↵`（Windows 为 `Ctrl+↵`）
4. 右侧看结论与逐项明细；下结论的词自动进「本次记录」，可一键导出 Markdown

想先看效果：点右上角「载入示例」，会填入一个公开关键词的实测值（`random country generator`，KD 54 / 外链 99 / 下降 / 专站首页为主），直接给出淘汰结论。

## 三、核心功能

| 功能 | 入口 | 一句话 |
| --- | --- | --- |
| 三档判定 | 顶部「严格 / 中等 / 宽松」 | 同一份数据按三套门槛各算一次，避免只用一把尺子 |
| 逐项明细 | 右侧「结论」卡片 | 每个硬指标给出门槛、实际值与超出的倍数 |
| 新词模式 | KD 字段下方开关 | KD 无数据时改用 intitle 供给量 + 前 10 结构判断 |
| 快捷取数 | 各字段旁的跳转按钮 | 复制关键词并打开对应站点，省去手输 |
| 截图取数 | KD、intitle 旁「截图取数」 | OCR 读 Ahrefs / 谷歌词结果数，填进对应字段 |
| 趋势识别 | 趋势形态旁「走势图」「CSV」 | 图像或 Google Trends 导出文件 → 9 类形态 + 置信度 |
| SERP 抓取分析 | 前 10 名构成旁「抓取分析」 | 粘贴 URL，按站点判定是专站还是大站内页 |
| 记录与导出 | 右侧「本次记录」 | 同词同档去重、最多 30 条；导出 Markdown 前 14 列与候选词表对齐，可直接粘贴 |
| 草稿与快捷键 | 自动 | 输入实时存 `localStorage`；`⌘↵` 判定；「清空」需点两次 |

各功能细节见第四节（参数）与第五节（输出），规则依据见第六节。

## 四、参数（输入）

### 4.1 实测数据字段

| 字段 | 控件（DOM id） | 必填 | 占位示例 | 校验规则 | 数据来源 |
| --- | --- | --- | --- | --- | --- |
| 关键词 | 文本 `kw` | ✅ | `pdf to word converter` | 非空；不含中文；≤ 80 字符 | Trends / 搜索结果原样复制 |
| Ahrefs KD | 数字 `kd` | ✅（新词模式禁用） | `54` | 0—100 的**整数** | `ahrefs.com/keyword-difficulty` 圆环数字 |
| 所需外链网站数 | 文本 `refdomains` | ✅（新词模式禁用） | `99` | ≥ 0 的整数；支持千分位 | 同一页 `…from ~N websites` 的 N |
| 趋势形态 | 下拉 `trend` | ✅ | 请选择… | 必选，9 个选项之一 | 人工判断 / CSV / 走势图 |
| 前 10 名构成 | 下拉 `serp` | ✅ | 请选择… | 必选，3 个选项之一 | 人工看 / 抓取分析 |
| intitle 结果数 | 文本 `intitle` | 常规选填、新词必填 | `1400` | 常规：填了必须 > 0 的整数；新词：≥ 0 的整数 | Google 搜 `intitle:"关键词"` |
| 月搜索量 | 文本 `volume` | 选填 | `20000` | 填了必须 > 0 的整数 | Google Ads / Trends 参照词估算 |
| 品牌词 | 复选 `brand` | 选填 | 未勾选 | — | 第 1 名是否为该词所指产品官网 |
| 前 10 有 Sitelinks | 复选 `sitelinks` | 选填 | 未勾选 | — | 结果标题下是否挂站内链接 |
| .com 可注册 | 复选 `domain` | 选填 | **默认勾选** | — | 注册商查询结果 |
| 取词来源 | 文本 `srcKw` | 选填 | `Trends 相关查询` | 无（不参与判定） | 怎么发现这个词 |
| 出现时间 | 文本 `firstSeen` | 选填 | `2026-09 / 老词` | 无 | 曲线从 0 抬起的时点 |
| 对比倍数 | 文本 `ratio` | 选填 | `3.5` | 无 | 同图对比参照词的倍数 |
| 估算日搜索量 | 文本 `dailyVol` | 选填 | `1200` | 无 | 倍数 × 参照词日搜索量 |

三点说明：

- `kd`、`refdomains`、`intitle`、`volume` 里只有 KD 是数字输入框，另三个是文本输入框 + 数字键盘，原因是能从 Google / Ahrefs 直接复制到 `1,400` 这种带千分位的写法，数字框会把整串丢掉。千分位在计算前自动去除。
- 趋势形态 9 个选项：上升、平稳、季节、下降、尖刺、驼峰、箱体震荡、多峰、阶梯上升（形态判据见 6.3）。
- 前 10 构成 3 个选项：专站首页为主 / 混合 / 大站内页为主。语义是"有没有人专门做这个词"。

### 4.2 门槛与附加规则

| 参数 | 控件 | 默认（严格档） | 作用 |
| --- | --- | --- | --- |
| KD 门槛 | `tKd` | `< 10` | KD 低于此值才通过 |
| 外链门槛 | `tRef` | `< 10` | 所需外链站数低于此值才通过 |
| KGR 门槛 | `tKgr` | `< 0.25` | 超过则计为风险项 |
| intitle 阈值 | `tAI` | `≤ 50` | 仅新词模式生效 |
| 品牌词一票否决 | `sBrand` | 开 | 勾选品牌词即直接淘汰 |
| 趋势下降/尖刺视为硬指标 | `sTrend` | 关 | 开启后 declining / spike / hump 直接淘汰 |
| 风险 ≥ N 项判为待定 | `sRisk` + `tRisk` | 开，N=2 | 硬指标全过但风险够多时给「待定」 |

切档会同时覆盖这 7 项；手动改动任意一项，界面右上角即标「自定义」，避免"看着是严格档、参数其实被改过"。

### 4.3 档位预设

| 档位 | KD | 外链站 | KGR | intitle | 趋势硬否决 | 品牌否决 | 风险门槛 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **严格**（第一个练手站） | < 10 | < 10 | < 0.25 | ≤ 50 | 开 | 开 | ≥ 2 → 待定 |
| **中等**（第二、三个站） | < 29 | < 25 | < 0.5 | ≤ 200 | 关 | 开 | ≥ 3 → 待定 |
| **宽松**（追新词/热点） | < 49 | < 50 | < 1 | ≤ 500 | 关 | 关（仅风险） | 不拦截 |

数值出处见 6.2。

### 4.4 快捷取数与关键词规范化

| 按钮 | 目标链接 | 是否自动带词 |
| --- | --- | --- |
| 查 Ahrefs（KD / 外链两处） | `https://ahrefs.com/keyword-difficulty` | ❌ 该站免费工具不读 URL 参数，改为**复制关键词到剪贴板**，打开后 `⌘V` 回车 |
| 看 Trends | `trends.google.com/trends/explore?date=today 12-m&hl=en&q=<词>` | ✅ 默认近 12 个月 |
| 看搜索结果 | `google.com/search?hl=en&num=20&q=<词>` | ✅ |
| 搜 intitle | `google.com/search?hl=en&num=20&q=intitle%3A%22<词>%22` | ✅ 引号由程序添加 |

关键词处理（`normalizeKw`）：全角空格→半角、去零宽字符、折叠连续空白、去首尾中英文引号、超 200 字符截断；拼接 intitle 查询时额外剔除词内 `"`；最终 `encodeURIComponent` 整体编码。

异常处理：关键词为空则按钮置灰（被程序调用也只提示不跳转）；未知工具标识提示「链接生成失败」；剪贴板不可用时降级 `execCommand('copy')`，仍失败则提示手动输入，跳转照常。

## 五、输出

### 5.1 结论卡片

结论区（`#verdict`）由四部分组成：状态徽标、理由句、三档对比 chips、提示行。

**状态徽标**（判定优先级从上到下，命中即停）：

| 徽标 | 触发条件 |
| --- | --- |
| `待输入` | 初始状态或点了「清空」 |
| `校验未通过` | 有字段不合法，列出全部问题（不是只报第一个） |
| `淘汰` | 品牌词一票否决，**或**任一硬指标不达标 |
| `待定` | 硬指标全过，但风险项数量 ≥ 门槛 |
| `通过（带 N 项风险）` | 硬指标全过，风险项未达门槛但 > 0 |
| `通过` | 硬指标全过且无风险项 |

**理由句**：淘汰时逐条列出未达标项与超出倍数；待定时列出全部风险项；通过时说明"未发现风险项"或风险清单。

**三档 chips**：用当前这份数据分别按严格 / 中等 / 宽松算一遍，给出三档结论。当前档位高亮。作用是回答"是我标准太严，还是这词确实不行"。

**提示行**（`#vHint`，按优先级取第一个非空）：

1. 当前判淘汰、但更宽松的档位能过 → 写出"在中等/宽松档下为通过，关键差距是 X"
2. 数据自洽提示（KGR 异常偏高、KD 低但全是专站、外链 0 但 KD 高、intitle 远大于月搜索量、新词 `intitle=0` 等）
3. 待定时说明"规则未给出明确结论，请逐条评估风险"

### 5.2 明细行

右侧表格逐项列出。常规模式 8 行，新词模式 7 行：

| 常规模式 | 新词模式 |
| --- | --- |
| Ahrefs KD（门槛、实际值、超出倍数） | intitle 供给量（阈值 ≤ N，实际条数，≤ 5 条标「无人防守」） |
| 所需外链网站数（同上） | 前 10 构成（专站首页为主即淘汰） |
| 趋势形态（是否被硬指标拦截） | 趋势形态 |
| intitle 结果数 | Ahrefs KD → `N/A`「新词模式：不参与判定」 |
| KGR（值 + 是否高于门槛；缺月搜索量时显示 `—`） | 所需外链网站数 → `N/A` |
| 前 10 构成（内页为主会标注"= 没有专站 = 机会"） | 品牌词 / Sitelinks |
| 品牌词 / Sitelinks | 风险项合计 |
| 风险项合计 | — |

另有一条 **KD 刻度尺**（`#kdGauge`）：0—100 刻度、浅色区表示门槛内的可做区、游标是当前 KD。新词模式或空值时自动隐藏。

### 5.3 记录与导出

- **本次记录**：只有主动点「判定」/按快捷键才入列（改字段触发的自动重算不入列）。同关键词 + 同档位视为同一条，重复判定会覆盖旧值，最多保留 30 条。点击任一条可回填当时的数据与规则。
- **导出**：下载 `keyword-records-YYYYMMDD.md`，按判定时间正序排列，末尾附当时使用的规则。前 14 列按候选词表的列序排列，可直接粘进表格；末两列为判定时间与档位（便于事后核对，不影响粘贴）。

| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | preset editor capcut | Trends 相关查询 | 2026-09 | 3.5 | 1,200 | 上升 | 40 | — | N/A（新词） | N/A | 大站内页为主 | 可 | 通过（带 1 项风险） | 11-17 10:04 | 严格 |

字段约定：`intitle 结果数` 未填显示「未查」，新词记录的 KD / 外链写 `N/A（新词）` / `N/A`，取词信息四项未填显示「—」，时间格式 `MM-DD HH:mm`。

### 5.4 代理接口输出

`src/worker.js` 暴露两个接口，前端「抓取分析」调用第一个。

`GET /api/fetch-page?url=<目标>`

```json
{
  "ok": true,
  "requested": "https://example.com/",
  "finalUrl": "https://example.com/",
  "status": 200,
  "contentType": "text/html; charset=utf-8",
  "bytes": 577,
  "truncated": false,
  "ms": 5,
  "html": "<!doctype html>…"
}
```

| 状态码 | 触发条件 | 响应体 |
| --- | --- | --- |
| 200 | 上游 2xx | 上述结构，`html` 已截断至 700 KB |
| 400 | 缺 `url` / URL 格式无效 / 非 http(s) | `{ok:false,error}` |
| 403 | 内网与回环地址、非 80/443 端口、IPv6 | `{ok:false,error}` |
| 405 | 非 GET（OPTIONS 预检返回 204） | `{ok:false,error:"仅支持 GET"}` |
| 429 | 触发限流 | `{ok:false,error}` |
| 502 | 上游非 2xx、超时（15s）、DNS/证书错误、非 HTML | `{ok:false,error,...}` |

`GET /api/health` → `{"ok":true,"service":"keyword-judge","time":"…"}`

## 六、判定规则细节

### 6.1 硬指标与风险项（代码口径）

**硬指标**（任一不达标即淘汰）：

| 模式 | 三项硬指标 |
| --- | --- |
| 常规 | KD `<` 门槛、所需外链站 `<` 门槛、趋势形态（仅当「趋势硬否决」开启时把 declining / spike / hump 视为不达标） |
| 新词 | intitle 供给量 `≤` 阈值、前 10 构成 `≠` 专站首页为主、趋势形态（同上） |

**风险项**（计入风险总数，不单独决定淘汰）：

1. 品牌词且未开启一票否决 → 「官方站点占据首位」
2. 前 10 有 Sitelinks
3. 前 10 为「混合」
4. 常规模式下前 10 全为专站首页
5. 趋势为季节 / 多峰 / 箱体震荡
6. KGR 高于门槛（常规模式）
7. .com 已被注册
8. 新词模式下 `intitle` 在 6 — 阈值之间（原话：供给不算空白）

### 6.2 数值出处

| 规则 | 出处（教程章节） |
| --- | --- |
| `KD < 10`、`外链站 < 10` | 《第 2 步》「看竞争对手强弱：KD + 亲眼看搜索结果」；《第 1 步》新手村阶段表（数据引自《【哥飞解答】第一个出海站》） |
| `KGR < 0.25 / 0.25—1 / > 1` | 《第 2 步》「看网页供应量：intitle 与 KGR」（数据引自《奥赛的经验分享》，2024-11-26） |
| 趋势三形态（季节 / 短暂爆火 / 走下坡路） | 《第 2 步》「看趋势形态，排除假机会」 |
| `KD < 29`（保小图大） | 《第 2 步》「老词怎么挖长尾」 |
| Sitelinks 为负面信号、品牌词难取首位 | 《第 2 步》「直接去谷歌搜索，亲眼看前 10 名」 |
| 候选表列名 | 《第 2 步》开头「一张候选词表」 |

> 仓库 `qiayue/OpenGeFei` · 分支 `claude/ecstatic-gauss-12hlsv` · commit `4b9243a6737824957b937864c9446c0ce2c3be45`

**教程未规定、由本项目设定**：中等档外链 25 与 KGR 0.5、宽松档 49 / 50 / 1 / 500、新词模式的 intitle 阈值、「趋势下降视为硬指标」、「风险计数」机制。教程对这类词的判断是「并非不可做，关键在于了解其热度特征」，因此趋势硬否决默认关闭。

### 6.3 趋势形态（9 类）

判定以 X 轴（时间结构）为主：峰持续时长（月）、相邻峰间隔（月）、峰位百分比、峰个数、斜率方向与 R²。

| 判据类别 | 具体特征 | 用途 |
| --- | --- | --- |
| 峰持续时间 | 峰宽 × 单点时长（换算成月） | 区分尖刺与驼峰 |
| 峰间隔 | 相邻峰时间距离（月） | 季节（≈12 个月）与多峰（< 9 个月） |
| 峰出现位置 | 峰在全程的百分比 | 前段爆发 / 中途冲高 / 末段拉升 |
| 峰数量 | 显著峰个数（阈值 均值 + 0.4σ） | 多峰 → 需求不稳定 |
| 全程走势 | 线性斜率符号与 R² | 上升 / 下降 / 横盘 |

**幅值类规则只在 CSV（真值）下启用**，图像模式降权（置信度 × 0.92）：

| 形态 | 真值模式判据 | 图像模式 |
| --- | --- | --- |
| 尖刺 | 峰持续 ≤ max(0.6 个月, 全程 3%) 且 峰值/中位数 ≥ 2.5 | 同（与幅值无关） |
| 驼峰 | 峰值/中位数 ≥ 2、峰位 25%—75%、末段/中段 < 0.75、峰持续 > 全程 5% | 同 |
| 季节 | 相邻峰间隔 9—15 个月，或 12 个月自相关 > 0.35 | 同 |
| 多峰 | ≥ 2 峰且间隔 1.5—9 个月 | 同 |
| 上升 | 全程上升 > 45 点且 R² > 0.55（弱档 > 20 点且末段/中段 > 1.5） | 只看方向：斜率符号 + R² > 0.5 |
| 下降 | 全程下降 > 45 点且 R² > 0.5（弱档 > 20 点且末段/中段 < 0.6） | 同上升，方向相反 |
| 箱体震荡 | \|变化\| < 20 点、波动系数 < 0.5、峰值/中位数 < 2.5 | \|相对斜率\| < 0.15 且峰值/中位数 < 2.5 |
| 阶梯上升 | 上升 > 20 点、R² < 0.5、末段/中段 > 1.5 | 不判定 |
| 平稳 | \|变化\| < 10 点、波动系数 < 0.35 | \|相对斜率\| < 0.12 且波动系数 < 0.35 |

低热度提醒：CSV 模式下全程峰值 ≤ 5/100 时提示"热度极低，形态成立也可能没有搜索量"。

**Y 轴口径**：Google Trends 的 Y 轴恒为 0—100，100 = 该次查询自身最高点。同一张图内可比相对高低，**跨关键词不可比绝对热度**，因此不能用"峰值多高"判断需求大小。

## 八、新词模式与数据导入

### 8.1 新词模式（KD 无数据时）

**问题**：Ahrefs 对新词或极低搜索量词返回 `No data`。这不是难度 0，而是**数据不足**。硬把 KD 填 0 会被判"通过"，属于错误结论。

**开启**：KD 字段下方开关，或「门槛与附加规则」里的同名开关，两处互为镜像。

| 项目 | 常规模式 | 新词模式 |
| --- | --- | --- |
| Ahrefs KD | 必填，硬指标 | 置灰 `N/A`，不参与判定 |
| 所需外链网站数 | 必填，硬指标 | 置灰 `N/A`，不参与判定 |
| intitle 结果数 | 选填，仅算 KGR | **转必填**，作为供给量进入硬指标 |
| 前 10 构成 | 软指标（计风险） | **转硬指标**：专站首页为主直接淘汰 |
| KGR | 计算并展示 | 不计算（无搜索量基准） |
| 结论 | — | 末尾追加「（新词模式：未使用 KD 与外链数据，属定性判断）」 |

关闭后 KD / 外链原值自动恢复（暂存在 `dataset.keep`），可反复开关。

**取值方式**：Google 搜 `intitle:"preset editor capcut"`（整串加引号）→ 点「工具」读结果数。引号不能省：`intitle:` 只约束紧跟的一个检索单位，加引号后整串词才成为一个单位。

> **等价写法** `allintitle:"…"`，两者计数通常接近。KGR 原始定义（Doug Cunnington）写的是 `(# of allintitle results)/(search volume)`，而教程第 2 步首选 `intitle:`；工具跟随教程用 intitle。选定一种后前后一致即可。

**限制**：新词模式是定性判断，不能回答"难度几分"，只能回答"供给是否空白、前 10 有没有人占位"，配套要求是早做、快速上线。

### 8.2 数据导入入口的位置

所有导入按钮都放在**它所服务的字段旁**：

| 维度 | 字段 | 按钮 | 行为 |
| --- | --- | --- | --- |
| 竞争度 | Ahrefs KD | 查 Ahrefs、截图取数 | 截图取数只填 KD 与外链数（同属 Ahrefs 一页） |
| 需求趋势 | 趋势形态 | 走势图、CSV | 走势图展开面板后可拖入/粘贴；CSV 直接弹文件选择 |
| 搜索结果 | 前 10 名构成 | 看搜索结果、抓取分析 | 前者开 Google，后者抓 URL |
| 供给量 | intitle 结果数 | 搜 intitle、截图取数 | 截图取数只填 intitle |

交互约定：识别结果在字段下方内联显示（如「已识别 2 项：KD 54、外链站 99」），自动填入的值标黄底、手动改动后去色；趋势面板右上角 `×` 收起。

### 8.3 CSV 导入（最准）

Google Trends 右上角下载 → `multiTimeline.csv` → 趋势形态旁「CSV」。

解析规则：去 BOM、兼容 `\r\n`；只取首列为 `YYYY-MM-DD` 的行；空值跳过；`<1` 按 0.5 处理；时间跨度按 30.44 天/月折算；数值直接使用真实 0—100 指数（不做归一化）。

与图像识别的关系：两条路径共用 `trendFeatures + classifyTrend`，但数值口径不同，结论可能不同——CSV 用真值、幅值规则全开；图像用相对高度、幅值规则降权、置信度 ×0.92。实测同一关键词：CSV「驼峰 70%」、图像「驼峰 64%」，形态一致、置信度更低。

### 8.4 走势图识别

**输入要求**

| 项 | 要求 | 原因 |
| --- | --- | --- |
| 来源 | Google Trends 截图最佳 | 依赖线条色值 `rgb(66,133,244)` |
| 宽度 | ≥ 800px | 低了曲线会糊；不足时仍出结论，但状态行附警告 |
| 内容 | 完整曲线 + 时间轴 | 时间轴跨度用于算 12 个月周期 |
| 时间范围 | 上传前在面板选（7 天 / 90 天 / 12 个月 / 5 年） | 选错会让「季节」失效，其他形态不受影响 |
| 避免 | 深色模式、滤镜、截图选中高亮 | 破坏颜色识别 |

**输出**：主形态 + 置信度（< 60% 用黄色提示）、修饰标签（末段拉升 / 末段回落 / 峰值突出 / 无长期趋势 / 波动较大 / N 个峰）、主判据一句话、次选形态及依据、数据质量（覆盖率、图宽），并给「填入趋势形态」按钮。

### 8.5 SERP 抓取分析（前 10 名构成）

在「前 10 名构成」旁点「抓取分析」→ 面板里粘贴 URL（每行一个，按排名顺序）→ 点「开始分析」。

**为什么需要你提供 URL**：本工具自己搜不了，实测过的通道：

| 通道 | 结果 |
| --- | --- |
| Google 直连 | JS 壳页；无头浏览器触发验证码 |
| Bing | HTTP 200，但返回与查询无关的缓存页 |
| DuckDuckGo / Qwant / Ecosia | 422 反爬标记 / 403 |

**判定规则**（与 `~/.workbuddy/skills/serp-homepage-check/scripts/serp-check.js` 同一套，改规则时两边都要改）：

专站分 = 根路径 +2、域名含核心词 +2（命中 ≥2 个再 +1）、标题命中 ≥60% +2（≥40% +1）、H1 含关键词 +1、导航 ≥25 个 −1、UGC 或知名大站 −3。

类型按顺序判：被拦截 → UGC 社区 → 大站内页 → 官方产品站 → 专站首页（分 ≥5）→ 工具页（内页）→ 内容博客 → 多产品/门户 → 其他。

汇总按**最终域名去重**（同站多页只算一个站点）；构成判定：专站 ≥ 5 → 专站首页为主；专站 ≥ 1 或（专站 + 官方站）≥ 2 → 混合；否则大站内页为主。点「填入构成」写回下拉框。

**两类不计入统计**：抓取失败（DNS / 超时 / 4xx，列出原因）；反爬验证页（Reddit 的 Prove your humanity、Cloudflare 的 Just a moment 等，标为「被拦截」并提示人工确认）。

**代理的安全边界**（`src/worker.js`）：仅 http/https + 80/443；拦截 `127.*`、`10.*`、`172.16—31.*`、`192.168.*`、`169.254.*`、`100.64—127.*`、`224.*` 及以上、IPv6、`localhost`、`*.local`、`*.internal`、`metadata.google.internal`；超时 15 秒；响应截断 700 KB；只接受 `text/html`、`application/xhtml+xml`、`text/plain`。

**已知限制：抓不了同一 Cloudflare zone 下的 `*.workers.dev` 站点。** 代理运行在 Worker 里，向同 zone 的另一个 Worker 发子请求会被 Cloudflare 拦下，返回 `error code: 1042`（接口层 502，面板显示失败）。`*.workers.dev` 共用 `workers.dev` 一个 zone，所以自己名下的 workers.dev 站点都抓不到；外部域名（example.com、iana.org 实测正常）不受影响。本机联调请用 `wrangler dev`，或给站点绑自定义域。

## 十一、已知限制

- **能抓首页，不能搜 SERP**。判定数据仍靠人工输入。
- **代理对反爬站点无能为力**。Reddit、Cloudflare 保护的站点会返回验证页，这类结果标「被拦截」并排除出统计。
- **OCR 准确率有限**。多栏紧凑截图、缩放图、非英文界面容易出错，识别值一律标黄待核。
- **KGR 无搜索量上限**。KGR 原始定义限定月搜索量 < 250，本工具不设该上限，高搜索量词会算出虚低 KGR。
- **趋势图像是相对高度**。未读 Y 轴刻度，幅值类判断降权。
- **门槛是社群经验值**，不是实验结论，可按自己的外链能力调整。
- **平台限制**：抓不了同 zone 的 `*.workers.dev`（见 8.5）。
