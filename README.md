# keyword-judge · 关键词判定器

出海建站用的**关键词可行性判定器**。填进实测数据（KD、所需外链网站数、趋势形态等），按三档标准输出「通过 / 待定 / 淘汰」，并给出逐项理由与可直接粘进记录表的 Markdown 行。

单文件静态页，零构建、零后端、无第三方依赖（截图识别按需从 CDN 加载 Tesseract.js）。

- 线上地址：<https://keyword-judge.sevenqi0728.workers.dev>
- 本地打开：直接双击 `public/index.html`

---

## 一、它解决什么问题

选词决定上限。建站、优化、外链都只是在放大一个选择——**选择错了，后面每一步都是浪费**。

判断一个词值不值得做，需要看四五项独立指标，且每项都有门槛。人脑记不住这些门槛，容易凭感觉放行。这个工具把门槛固定下来，把判断过程显性化：哪一项过了、哪一项超了、超了几倍，全部写出来。

## 二、三档标准

| 档位 | KD | 所需外链站 | KGR | 趋势下降/尖刺 | 品牌词 | 风险门槛 |
| --- | --- | --- | --- | --- | --- | --- |
| **严格**（第一个练手站） | < 10 | < 10 | < 0.25 | **硬否决** | 一票否决 | ≥2 项 → 待定 |
| **中等**（第二、三个站） | < 29 | < 25 | < 0.5 | 仅警告 | 一票否决 | ≥3 项 → 待定 |
| **宽松**（追新词/热点） | < 49 | < 50 | < 1 | 仅警告 | 仅警告 | 不拦截 |

切换档位会同时重置门槛数字与三个开关。手动改动任意一项后，界面标记为「自定义」，避免出现「看着是严格档、参数其实被改过」的误读。

## 三、使用

1. 在 Google Trends 找候选词，在谷歌、Ahrefs 取数
2. 把数据填进左侧（带 `*` 为必需）
3. 点「判定」或按 `⌘↵`
4. 右侧给出结论、三档对比、逐项明细；点「复制这一行」粘进记录表

**取值说明**（界面每个字段旁的「?」也有同样内容；界面上必填项在前，选填项在后）：

| 字段 | 必填 | 怎么取 |
| --- | --- | --- |
| 关键词 | ✅ | 从 Trends 或搜索结果里原样复制英文词，不翻译、不加引号 |
| Ahrefs KD | ✅ | `ahrefs.com/keyword-difficulty` 输入关键词，看圆环数字（0—100） |
| 所需外链网站数 | ✅ | 同上页面 `…need followed backlinks from ~N websites` 里的 N |
| 趋势形态 | ✅ | Trends 拉 12 个月与 5 年，判断季节 / 尖刺 / 下降 / 平稳 |
| 前 10 名构成 | ✅ | 谷歌搜这个词，看前 10 是专站首页还是大站内页 |
| intitle 结果数 | 选填 | 谷歌搜 `intitle:"关键词"`（带引号）→ 点「工具」→ 右下角「找到约 X 条结果」，仅用于算 KGR |
| 月搜索量 | 选填 | 没有 Ads 账号时用 Trends 参照词估算；留空则跳过 KGR |
| 附加标记 | 选填 | 品牌词 / 有 Sitelinks / .com 可注册，用于风险计数 |

### 其它功能

- **截图识别**：点击 / 拖入 / `⌘V` 粘贴截图，尝试自动填 KD、外链数、intitle 数、趋势方向。识别值标黄底，需人工核对。引擎为 Tesseract.js（首次需联网加载数 MB），失败时明确提示手动填写。
- **本次记录**：主动判定过的词进入右侧列表，点击可回填当时的数据与规则；「导出记录」下载 Markdown。
- **草稿自动保存**：输入内容存在 `localStorage`，重开页面自动恢复。

## 六、已知限制

- **判定逻辑不联网**，数据全靠人工输入。不要期待它替你去查——谷歌搜索、Ahrefs、Trends 都有反爬或无公开 API（详见项目讨论：全自动取数的真实成本是每月几十美元的 API 费用）。
- **OCR 准确率有限**。多栏紧凑截图、缩放过的图片、非英文界面容易出错，因此识别结果一律标黄待核对。追求高准确率请把截图直接交给具备视觉能力的模型。
- **门槛是社群经验值，不是实验结论**。`10` 这个数字的含义是「新手基准」，不是物理常数，可随时按自己的外链能力调整。
